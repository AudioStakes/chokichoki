# 折り紙アニメーション要件整理

このドキュメントは、`chokichoki` リポジトリの `prototype` フォルダーに追加する折り紙プロトタイプの要件整理です。

想定配置先:

```text
chokichoki/
  prototype/
    origami-fold-cut-demo/
      REQUIREMENTS.md
```

---

## 1. 基本コンセプト

このアプリは、子ども向けの完成UIではなく、**折り紙の折る・切る・開く挙動を検証するための技術プロトタイプ**です。

目的は、以下を視覚的に確認できることです。

- 折り紙を縦方向・横方向に任意順で折れる
- 折った状態でハート型に切れる
- 切った穴が重なった紙の層に反映される
- 開いたときに、各層の位置・向きに応じたハート穴が現れる
- 折りたたみ状態から展開状態まで、アニメーションとプログレス操作で確認できる

見た目の優先度は、装飾よりも **折り紙としての挙動の分かりやすさ** です。

---

## 2. 表示・視点の要件

### 2.1 初期表示

初期表示では、折り紙を **真正面** から見る。

- 紙面が画面に対してほぼ平行に見える
- 斜め視点から始めない
- ユーザーが最初に見たとき、1枚の正方形の折り紙として認識できる

理由は、斜め視点だと折り紙の状態や切り抜き位置が分かりにくくなるためです。

### 2.2 視点操作

ユーザーはドラッグ操作で3D視点を変更できる。

要件:

- ドラッグでカメラを回転できる
- ホイールでズームできる
- 初期状態は正面だが、必要に応じて斜めから確認できる
- ドラッグ中に誤ってハートカットが発火しない

クリックとドラッグは移動量で判定を分ける。

- 小さい移動量: クリック扱い
- 一定以上の移動量: カメラ操作扱い

### 2.3 背景

背景は白。

- 折り紙の水色が見やすいこと
- ハート型の切り抜きが背景色として白く抜けて見えること
- 技術デモとして余計な装飾を入れないこと

---

## 3. 折り紙の見た目の要件

### 3.1 紙の色

折り紙は水色で表示する。

現在の要件では、表裏とも水色固定。

理由:

- 表裏を別色にすると、描画ブレやちらつきが出た
- Z-fighting の原因になる重複メッシュを避けたい
- まずは切り抜きと折り挙動を優先する

### 3.2 1枚の紙に見えること

内部的には複数パネルに分割してもよいが、見た目はなるべく **1枚の紙** に見えること。

避けたい表示:

- 16分割や64分割の線が見える
- パネル間の隙間が見える
- ワイヤーフレームが見える
- 折り線以外の不自然な格子が見える

実装上は内部パネルを使うが、表示では以下を行う。

- ワイヤーフレームを表示しない
- パネルサイズをわずかに重ねて隙間を目立たせない
- 折り線補助線も基本的に非表示
- 影や照明による分割線が出にくいマテリアルを使う

### 3.3 紙の厚み

このプロトタイプでは紙の厚みは必須ではない。

優先するのは、

- 折る面の動き
- 切り抜き位置
- 展開時の穴の位置と向き

であり、厚みのリアリティは後回しでよい。

---

## 4. 内部モデルの要件

### 4.1 内部分割

折り紙は内部的に複数の小パネルとして扱う。

現在の方針:

- `8 × 8` 分割
- 各パネルは独立した Three.js mesh / group として扱う
- 各パネルごとに折り変換行列を適用する

理由:

- 縦3回・横3回の折りに対応しやすい
- ハート穴が内部パネル境界をまたぐ場合に処理しやすい
- 展開時に各領域の位置・向きを個別管理できる

### 4.2 3D表示だけを正解にしない

状態管理は、見た目の3D mesh だけに依存しない。

管理すべき状態:

- 折り履歴
- 折り方向
- 各折りの順番
- 各折りのアニメーション進行
- カット位置
- カット対象パネル
- カット時の層ごとの向き
- 展開スクラブの進行度

3D mesh はあくまで表示結果であり、状態は明示的なデータとして持つ。

## 5. 折るアニメーションの要件

### 5.1 折り方向

ユーザーは以下を自由に選べる。

- 縦に折る
- 横に折る

固定順ではない。

例:

- 縦 → 横 → 縦
- 横 → 横 → 縦
- 縦 → 縦 → 縦
- 横 → 縦 → 横 → 縦

など、ユーザーが選んだ順に折り履歴を積み上げる。

### 5.2 折り回数の上限

上限は以下。

- 縦折り: 最大3回
- 横折り: 最大3回

合計では最大6回まで折れる可能性がある。

ただし、それぞれの方向ごとに3回を超えてはいけない。

UI上では、

```text
縦に折る 0/3
横に折る 0/3
```

のように現在回数を表示する。

### 5.3 折り線の位置

折り線は、その方向で何回目の折りかによって変わる。

縦折りの場合:

- 1回目: 中央付近
- 2回目: 折りたたまれた領域の中央
- 3回目: さらに折りたたまれた領域の中央

横折りも同様。

現在の考え方では、紙のサイズを `PAPER_SIZE` として、

```text
crease = HALF_SIZE - PAPER_SIZE / 2^(axisFoldIndex + 1)
```

のように、折り回数に応じて折り線位置を決める。

### 5.4 折り方向の意味

「縦に折る」は、縦方向の折り線を軸にして左右方向に折る操作。

- 折り線は縦
- 回転軸は Y 軸方向
- 左側の領域を右側に重ねる

「横に折る」は、横方向の折り線を軸にして上下方向に折る操作。

- 折り線は横
- 回転軸は X 軸方向
- 下側の領域を上側に重ねる

### 5.5 折りアニメーション

折るときは、対象パネルを折り線まわりに3D回転させる。

要件:

- 一瞬で切り替えない
- 折り線を軸に回転していることが分かる
- 回転角はおおむね `π`、つまり180度
- easing を使って自然に動く
- アニメーション中だけ、折りの立体感が分かる

現在の easing 方針:

```text
easeInOutCubic
```

### 5.6 折り対象の判定

各パネルの現在位置を、それまでの折り変換後の座標で評価する。

つまり、

1. パネルの元の中心座標を取得
2. 既存の折り変換を順に適用
3. 現在の中心座標が折り線のどちら側にあるかを見る
4. 対象側なら次の折り回転を適用

これにより、折り履歴に応じて次に折る対象が変わる。

## 6. カットアニメーション・切り抜き要件

### 6.1 カット方式

赤いハート mesh を紙の上に置く方式ではなく、**紙そのものにハート形の穴を開ける** 表現にする。

現在の方式:

- 各内部パネルに `CanvasTexture` の alpha mask を持たせる
- 通常は白いマスクで紙を表示
- ハート形に黒く描いた部分を alpha により透明化
- 透明部分が穴として見える

これにより、

- ハートが立体的に浮いて見えない
- スタンプではなく切り抜きに見える
- unfold 後も穴として残る

### 6.2 カットモード

`♥ cut mode` を押すと、カットモードに入る。

要件:

- カットモード中は、紙をクリックするたびにハート穴を追加できる
- 1回切るたびにボタンを押し直す必要はない
- 連続で複数箇所を切れる
- reset するまで複数カットが残る

### 6.3 カット可能条件

カットは少なくとも1回折った後に可能。

理由:

- このプロトタイプは、折った紙を切って開く挙動を確認するもの
- 未折り状態の単純穴あけは主目的ではない

### 6.4 カット後の折り操作

カット後は追加の折り操作をロックする。

理由:

- 「折る → 切る → 開く」の工程を明確にするため
- 切った後にさらに折ると、状態管理とユーザー理解が複雑になるため
- まずは一般的な切り紙の流れを優先する

### 6.5 カット位置の管理

カット時には、クリック位置をワールド座標で取得する。

その後、対象となる各内部パネルに対して、

- `panelId`
- `localX`
- `localY`
- `localQuaternion`

を保存する。

`localX`, `localY` は、そのパネル上でのハート中心位置。

`localQuaternion` は、その層でのハートの向き。

### 6.6 ハートの向き

ここが重要。

切る瞬間は、ユーザーから見た一番上の層に対して **上向きのハート** として切る。

ただし、展開後はすべて上向きになるわけではない。

折り重なった層によっては、

- 上向き
- 下向き
- 左右反転
- 回転した向き

になるべき。

要件:

- カット時のトップ層の向きを基準にする
- 下層には、トップ層との差分回転を `localQuaternion` として保存する
- 展開後は、その保存された向きでマスクにハートを描く
- すべての穴を常に上向き固定にしない

理由:

折り紙を切った場合、物理的には同じハート形の刃で貫通していても、紙を開くと層ごとに向きが変わるため。

### 6.7 複数層のカット

折りたたまれた紙を切る場合、見えている一番上の面だけではなく、重なっている全層に穴が開く必要がある。

要件:

- Raycaster でクリックされたトップ面を取得する
- そのトップ面のワールド座標を基準にする
- その位置に重なっている各パネルを判定する
- 重なっている全パネルにカット情報を配る
- それぞれのパネルでローカル座標・ローカル向きへ変換する

### 6.8 内部パネル境界をまたぐカット

ハート穴が内部パネルの境界をまたぐ場合、中心点が入っているパネルだけに描くと穴が欠ける。

そのため、

- ハートの大きさ分の範囲を持つ
- 中心点だけでなく、ハートがかかる周辺パネルも対象にする
- 各対象パネルに、そのパネルのローカル座標で同じハートを描く

要件:

- パネル境界上でもハートが欠けない
- パネル境界をまたいでも連続した穴に見える
- 内部分割が見た目に影響しない

## 7. 開くアニメーションの要件

### 7.1 unfold all

`unfold all` を押すと、折り履歴を逆順で開く。

例:

```text
縦 → 横 → 縦
```

と折った場合、開く順番は

```text
最後の縦 → 横 → 最初の縦
```

つまり履歴の逆順。

### 7.2 開くアニメーション

各折り操作を逆再生する。

- 折るときに `progress: 0 → 1`
- 開くときは `unfold progress` によって `1 → 0`

として表示する。

内部的には、

```ts
active.type = "unfold";
active.index = 対象の折り履歴 index;
active.progress = 開き進行度;
```

のように扱う。

### 7.3 プログレスバー

`unfold all` 後にはプログレスバーを表示する。

要件:

- 0%: 完全に折りたたまれた状態
- 100%: 完全に開いた状態
- ドラッグで任意の展開状態に移動できる
- 自動再生中でも、ユーザーがドラッグしたらスクラブ操作を優先する
- 折り履歴に基づいて正しい中間状態を表示する

### 7.4 スクラブ操作

プログレスバーの値から、現在どの折りをどれだけ開いているかを計算する。

例: 折り回数が `N` のとき

```text
scaled = progress * N
segment = floor(scaled)
segmentProgress = scaled - segment
index = N - 1 - segment
```

これにより、

- 最後に折ったものから順に開く
- 中間状態も連続的に表示できる

## 8. UI要件

### 8.1 ボタン

下部に操作ボタンを配置する。

必要なボタン:

- `縦に折る n/3`
- `横に折る n/3`
- `♥ cut mode`
- `unfold all`
- `reset`

### 8.2 折りボタンの無効化

以下のとき、折りボタンは disabled にする。

- その方向の折り回数が3回に達した
- 折りアニメーション中
- unfold 中
- カット済み
- カットモード中
- unfold スクラブ中

### 8.3 カットボタンの無効化

以下のとき、`♥ cut mode` は disabled にする。

- まだ1回も折っていない
- 折りアニメーション中
- unfold スクラブ中

### 8.4 reset

`reset` はすべての状態を初期化する。

初期化対象:

- 折り履歴
- 折り回数
- アクティブアニメーション
- カット情報
- カットモード
- pending cut
- unfold scrub
- unfold progress
- カメラ視点
- カットID連番

## 9. エラー・不自然挙動を避ける要件

### 9.1 90度の瞬間回転を出さない

折るアニメーション終了後に、紙が突然90度回転して見えるような切り替えを避ける。

要件:

- アニメーション中の姿勢と完了後の姿勢が連続している
- `active` から `committed` へ移るときに見た目がジャンプしない
- カメラや root rotation の急な変更をしない

### 9.2 色ブレを出さない

表裏のために同じ平面を2枚重ねると Z-fighting が起きるため避ける。

現在は、

- 表裏とも同じ水色
- 1枚の不透明メッシュ
- alpha mask による穴表現

を優先する。

### 9.3 ハートが立体物として見えない

ハートは mesh として置かない。

避けること:

- 赤いハートを紙の上に載せる
- ハートが浮いて見える
- 複数層のハート mesh が重なって見える
- ハートが立体物として見える

必ず、紙の alpha mask として切り抜く。

### 9.4 内部パネル境界で穴が欠けない

内部パネル単位で穴を描くため、境界をまたぐ場合は周囲パネルにもカットを配る。

これをしないと、

- ハートの一部だけ欠ける
- 切れたり切れなかったりして見える
- 内部分割が露出する

ため、必須要件。

## 10. 実装上の主要データ構造

### 10.1 foldOps

ユーザーが押した順に折り履歴を保存する。

各 fold op は以下を持つ。

```ts
{
  id: string;
  name: string;
  direction: "vertical" | "horizontal";
  line: number;
  axis: [number, number, number];
  point: [number, number, number];
  angle: number;
}
```

### 10.2 cuts

各カット情報は以下を持つ。

```ts
{
  id: string;
  panelId: number;
  localX: number;
  localY: number;
  localQuaternion: [number, number, number, number];
}
```

複数層に貫通した場合、1回のクリックで複数の cut が追加される。

### 10.3 active

現在アニメーション中の折りを表す。

```ts
{
  type: "fold" | "unfold";
  index: number;
  progress: number;
}
```

## 11. 今後の改善候補

現時点ではプロトタイプとして十分だが、将来の改善候補は以下。

- 本物のジオメトリ穴あけにする
- 紙の厚みを追加する
- 表裏色を再導入する
- 切り抜き縁に少し影をつける
- カット形状を複数選べるようにする
- 折り方向を左右・上下どちらに倒すか選べるようにする
- 折り線を一時的に表示するモードを追加する
- スマホ操作に最適化する
- 最終的な展開図を2D表示として出す
- 切った後もさらに折れるモードを追加する

現時点では、**折る → 切る → 開く** の理解しやすさを優先し、追加折りや複雑な編集は制限する方針です。
