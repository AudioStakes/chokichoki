# Implementation Notes

## レンダリング

- 紙は薄い平面メッシュとして扱う。
- 見た目上の厚みは外周表現や影で補う。
- 切り抜き穴の断面は表現しない。
- 折る途中は、対象面を折り線軸で回転させる。
- 紙のしなりは最初の版では扱わない。

## 穴の描画

- 切り抜きは白い穴として表示する。
- 実際にメッシュをブーリアン演算で切るか、マスク/シェーダー/2Dテクスチャとして扱うかは実装検証で決める。
- ただし、正確な切り抜きデータは必ず2D幾何モデル側に保持する。

## カメラとライト

- カメラは固定。
- 折る・開く途中でもカメラは動かさない。
- 完成時は正面から見せ、紙を少し拡大する。
- 光は固定で、左上からやわらかく当てる。
- 影はやわらかい落ち影にする。

## パフォーマンス

- スマホ優先。
- 折る・ひらく中に過剰な物理演算を行わない。
- 紙のしなりやリアルな積層厚みは扱わない。
- 操作中に60fpsに近い体感を目指す。

## PWA

- service workerで必要なアセットをキャッシュする。
- 効果音、アイコン、初期UIはオフラインで利用できるようにする。
- ローディング画面は出さない方針だが、初期表示が遅い場合は最小限の代替表示を検討する。

## テスト観点

- 折り順が固定通りであること。
- 切り抜きが重なっている全レイヤーに適用されること。
- 展開時に折り目に合わせて反転・鏡写しになること。
- 切り抜き数上限を超えたときに最古の切り抜きが置き換わること。
- アニメーション中に操作を受け付けないこと。
- 色変更で切り抜きが消えないこと。
